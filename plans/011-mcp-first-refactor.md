# Plan 011: MCP-First Refactor — Lean Data Layer for AI Agents

## Vision

OpenTrace should be the **one monitoring tool a small team installs** — replacing Sentry + Datadog + UptimeRobot — **queryable by AI agents via MCP**. The server is a lean, reliable data layer. The agent (Claude Code) is the intelligence.

Everything that doesn't serve this vision is weight to cut. Everything missing to achieve it gets added.

---

```sql
CREATE TABLE error_groups (
    fingerprint    TEXT PRIMARY KEY,
    service        TEXT NOT NULL,
    environment    TEXT NOT NULL DEFAULT '',
    exception_class TEXT NOT NULL DEFAULT '',
    message        TEXT NOT NULL DEFAULT '',
    source_file    TEXT NOT NULL DEFAULT '',
    source_line    INTEGER NOT NULL DEFAULT 0,
    status         TEXT NOT NULL DEFAULT 'unresolved',  -- unresolved, resolved, ignored
    first_seen_at  TEXT NOT NULL,
    last_seen_at   TEXT NOT NULL,
    occurrence_count INTEGER NOT NULL DEFAULT 1,
    last_log_id    INTEGER REFERENCES logs(id),
    reopened_count INTEGER NOT NULL DEFAULT 0,
    resolved_at    TEXT,
    ignored_at     TEXT
);
CREATE INDEX idx_error_groups_service ON error_groups(service, status);
CREATE INDEX idx_error_groups_last_seen ON error_groups(last_seen_at DESC);
CREATE INDEX idx_error_groups_count ON error_groups(occurrence_count DESC);

CREATE TABLE error_group_events (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    fingerprint  TEXT NOT NULL REFERENCES error_groups(fingerprint) ON DELETE CASCADE,
    action       TEXT NOT NULL,  -- 'resolved', 'ignored', 'reopened'
    reason       TEXT NOT NULL DEFAULT '',
    created_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))
);
CREATE INDEX idx_error_group_events_fp ON error_group_events(fingerprint, created_at DESC);
```

**Data model:**
```go
type ErrorGroupStatus string
const (
    ErrorGroupUnresolved ErrorGroupStatus = "unresolved"
    ErrorGroupResolved   ErrorGroupStatus = "resolved"
    ErrorGroupIgnored    ErrorGroupStatus = "ignored"
)

type ErrorGroup struct {
    Fingerprint     string           `json:"fingerprint"`
    Service         string           `json:"service"`
    Environment     string           `json:"environment"`
    ExceptionClass  string           `json:"exception_class"`
    Message         string           `json:"message"`
    SourceFile      string           `json:"source_file"`
    SourceLine      int              `json:"source_line"`
    Status          ErrorGroupStatus `json:"status"`
    FirstSeenAt     time.Time        `json:"first_seen_at"`
    LastSeenAt      time.Time        `json:"last_seen_at"`
    OccurrenceCount int              `json:"occurrence_count"`
    LastLogID       *int64           `json:"last_log_id,omitempty"`
    ReopenedCount   int              `json:"reopened_count"`
    Events          []ErrorGroupEvent `json:"events,omitempty"` // populated by error_detail
}

type ErrorGroupEvent struct {
    ID          int64     `json:"id"`
    Fingerprint string    `json:"fingerprint"`
    Action      string    `json:"action"`  // "resolved", "ignored", "reopened"
    Reason      string    `json:"reason,omitempty"`
    CreatedAt   time.Time `json:"created_at"`
}
```

**MCP tools:**
- `error_groups` — list error groups sorted by occurrence/last_seen, filterable by service/status/environment
- `error_detail` — get full error details including recent occurrences, stack trace, affected endpoints, and resolution history (events)
- `resolve_error` — mark as resolved with a reason; records an event. Auto-reopens if it recurs
- `ignore_error` — permanently ignore with a reason; records an event

**Upsert logic** (on log ingestion):
When a log entry has `error_fingerprint` set AND `level` is ERROR/FATAL:
- If fingerprint exists: increment `occurrence_count`, update `last_seen_at`, `last_log_id`
- If fingerprint exists AND status=resolved: reopen (set status=unresolved, `reopened_count++`, insert "reopened" event)
- If fingerprint doesn't exist: insert new row

## Phase 3: Improve — Agent Ergonomics

### 3.1 Add `diagnose` Meta-Tool

A single tool that bundles multiple data sources into one response, saving the agent 4-5 round trips.

**New files to CREATE:**

| File | Purpose |
|------|---------|
| `internal/mcp/tool_diagnose.go` | `diagnose` — all-in-one investigation tool |
| `internal/mcp/tool_diagnose_test.go` | Tests |

**Tool signature:**
```
diagnose(service, timeframe?)
```

**Returns (single JSON response):**
```json
{
  "service": "my_app",
  "timeframe": "1h",
  "error_summary": { "total_errors": 12, "new_fingerprints": 2, "top_errors": [...] },
  "watch_alerts": [...],
  "request_performance": { "p50_ms": 45, "p95_ms": 230, "slowest_endpoints": [...] },
  "log_volume": { "total": 1500, "by_level": {...}, "trend": "increasing" },
  "healthcheck_status": [...],
  "suggested_next_tools": ["error_detail", "trace_lookup", "explain_query"]
}
```

This replaces calling `log_summary` + `error_groups` + `watch_status` + `uptime_status` + `request_performance` individually.

### 3.2 Add `suggested_tools` to All MCP Responses

**Files to UPDATE:**

Every `tool_*.go` handler — append a `"suggested_tools"` array to responses based on what the tool found. **Include pre-filled arguments** so Claude Code can call them directly without figuring out what to pass.

| Tool | Condition | Suggested |
|------|-----------|-----------|
| `log_summary` | High error rate | `[{"tool": "error_groups", "args": {"status": "unresolved"}}, {"tool": "trace_lookup"}]` |
| `error_groups` | New unresolved errors | `[{"tool": "error_detail", "args": {"fingerprint": "abc123"}}, {"tool": "log_search", "args": {"level": "error"}}]` |
| `db_activity` | Long-running query PID 12345 | `[{"tool": "explain_query", "args": {"query": "SELECT ..."}}, {"tool": "kill_query", "args": {"pid": 12345}}]` |
| `request_performance` | N+1 detected | `[{"tool": "log_search", "args": {"endpoint": "/api/users"}}, {"tool": "trace_lookup"}]` |
| `watch_status` | Active alerts | `[{"tool": "diagnose", "args": {"service": "my_app"}}, {"tool": "log_search", "args": {"level": "error"}}]` |

This is a low-effort, high-value change. Add a helper:
```go
type ToolSuggestion struct {
    Tool string         `json:"tool"`
    Args map[string]any `json:"args,omitempty"`
}

func withSuggestions(resp map[string]any, suggestions ...ToolSuggestion) map[string]any {
    if len(suggestions) > 0 {
        resp["suggested_tools"] = suggestions
    }
    return resp
}
```

This becomes Claude Code's best tool for understanding *what happened and in what order* during an incident.
