# Watchers & Dashboard Refactor Plan

## Overview

Refactor OpenTrace into three distinct layers:

| Layer | Purpose |
|-------|---------|
| **Dashboard** | Manage connectors, view logs, create/manage watchers, view alerts |
| **MCP + Claude Code** | Interactive, ad-hoc investigation (user-driven) |
| **Watchers** | Automated, scheduled AI-powered monitoring (server-driven) |

The interactive investigation UI (SSE chat) is removed. Claude Code via MCP becomes the primary tool for ad-hoc debugging. The dashboard becomes a control plane for data sources, log browsing, and automated watchers.

```sql
-- Watcher schedule types
CREATE TYPE watcher_status AS ENUM ('active', 'paused', 'error');

CREATE TABLE watchers (

    severity        watcher_severity NOT NULL DEFAULT 'warning',

    filters         JSONB NOT NULL DEFAULT '{}',
    -- {
    --   "service": "payment-api",
    --   "level": "error",
    --   "environment": "production",
    --   "time_range": "15m",
    --   "query": "timeout OR connection refused"
    -- }

    -- Schedule
    interval_seconds INT NOT NULL DEFAULT 300,  -- how often to run (default: 5 min)
    status           watcher_status NOT NULL DEFAULT 'active',

    -- Notification config
    notify           JSONB NOT NULL DEFAULT '["dashboard"]',
    -- ["dashboard"]
    -- ["dashboard", {"type": "webhook", "url": "https://..."}]

    -- Tracking
    last_run_at     TIMESTAMPTZ,
    next_run_at     TIMESTAMPTZ,
    last_error      TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Individual watcher execution results
CREATE TABLE watcher_runs (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    watcher_id  UUID NOT NULL REFERENCES watchers(id) ON DELETE CASCADE,
    started_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at TIMESTAMPTZ,
    status      TEXT NOT NULL DEFAULT 'running',  -- running, completed, error
    summary     TEXT,           -- agent's summary of findings
    details     JSONB,         -- full tool call trace / raw findings
    has_alert   BOOLEAN NOT NULL DEFAULT false,
    error       TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_watcher_runs_watcher_id ON watcher_runs(watcher_id, created_at DESC);

-- Alerts generated by watchers (or manually)
CREATE TABLE alerts (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    watcher_id  UUID REFERENCES watchers(id) ON DELETE SET NULL,
    run_id      UUID REFERENCES watcher_runs(id) ON DELETE SET NULL,
    title       TEXT NOT NULL,
    summary     TEXT NOT NULL,
    severity    watcher_severity NOT NULL DEFAULT 'warning',
    details     JSONB,          -- structured findings
    read        BOOLEAN NOT NULL DEFAULT false,
    dismissed   BOOLEAN NOT NULL DEFAULT false,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_alerts_created_at ON alerts(created_at DESC);
CREATE INDEX idx_alerts_unread ON alerts(created_at DESC) WHERE read = false AND dismissed = false;
```

## Phase 2: Watcher Scheduler Engine

### 2.1 Scheduler

**File: `internal/watcher/scheduler.go`**

The scheduler runs as a background goroutine, polling for due watchers.

```go
type Scheduler struct {
    watcherStore    store.WatcherStore
    runStore        store.WatcherRunStore
    alertStore      store.AlertStore
    registry        *connector.Registry
    llmProvider     llm.LLMProvider   // default provider for watchers (Ollama)
    agentCfg        agent.RunConfig
    pollInterval    time.Duration     // how often to check for due watchers (default: 30s)
    maxConcurrent   int               // max concurrent watcher runs (default: 3)
}

func NewScheduler(opts SchedulerOpts) *Scheduler

func (s *Scheduler) Start(ctx context.Context)   // starts background loop
func (s *Scheduler) Stop()                        // graceful shutdown
```

**Loop logic:**
```
every pollInterval:
    watchers = watcherStore.GetDueWatchers()
    for each watcher (up to maxConcurrent via semaphore):
        go s.executeWatcher(ctx, watcher)
```

### 2.2 Watcher Execution

**File: `internal/watcher/executor.go`**

```go
func (s *Scheduler) executeWatcher(ctx context.Context, w store.Watcher) {
    // 1. Create a watcher_run record
    run := s.runStore.CreateRun(w.ID)

    // 2. Build tool set from registry (only relevant tools)
    tools := s.registry.AllTools()

    // 3. Fetch last run summary for context continuity
    lastRuns := s.runStore.ListRuns(w.ID, 1)  // most recent completed run
    var lastRunSummary string
    if len(lastRuns) > 0 && lastRuns[0].Summary != nil {
        lastRunSummary = *lastRuns[0].Summary
    }

    // 4. Build the watcher prompt from its description + filters + previous context
    query := buildWatcherQuery(w, lastRunSummary)

    // 5. Run agent loop
    ag := agent.New(s.llmProvider, s.agentCfg)
    answer, err := ag.Run(ctx, query, tools)

    // 5. Evaluate result — does it warrant an alert?
    hasAlert := evaluateFindings(answer, w.Severity)

    // 6. If alert, create alert record + send notifications
    if hasAlert {
        alert := s.alertStore.CreateAlert(CreateAlertParams{
            WatcherID: &w.ID,
            RunID:     &run.ID,
            Title:     w.Title,
            Summary:   answer,
            Severity:  w.Severity,
        })
        s.notify(ctx, w, alert)
    }

    // 7. Complete the run
    s.runStore.CompleteRun(run.ID, answer, details, hasAlert)

    // 8. Update watcher next_run_at
    next := time.Now().Add(time.Duration(w.IntervalSeconds) * time.Second)
    s.watcherStore.UpdateWatcherRunTime(w.ID, time.Now(), next)
}
```

### 2.3 Watcher Prompt Builder

**File: `internal/watcher/prompt.go`**

Translates watcher config into an agent query:

```go
func buildWatcherQuery(w store.Watcher, lastRunSummary string) string {
    // Example output:
    //
    // You are a monitoring agent. Evaluate the following condition:
    //
    // ## Watcher: Payment failures spike
    // Check if payment gateway errors exceed normal rate.
    // Look for patterns in failing merchant IDs or error codes.
    //
    // ## Search Scope
    // - Service: payment-api
    // - Level: error
    // - Time range: last 15 minutes
    //
    // ## Previous Run (5 minutes ago)
    // Found 12 payment errors, mostly timeout-related. Normal rate.
    //   ← injected from lastRunSummary (omitted if first run)
    //
    // ## Instructions
    // 1. Use log_search with the filters above to find matching logs
    // 2. Compare findings to the previous run — note any changes or trends
    // 3. Use memory_read to check for known patterns, memory_write to save new ones
    // 4. Respond with your assessment:
    //    - ALERT: if the condition is met and action is needed
    //    - OK: if everything looks normal
    // 5. Include a brief summary of what you found and how it compares to last run
}
```

### 2.4 Alert Evaluation

The agent's response is parsed to determine if an alert should fire:

```go
func evaluateFindings(answer string, severity string) bool {
    // Simple heuristic: check if agent response starts with or contains "ALERT:"
    // The prompt instructs the agent to prefix with ALERT: or OK:
    return strings.Contains(strings.ToUpper(answer), "ALERT:")
}
```

This keeps it simple. The LLM decides whether the condition is met based on the watcher's description. No complex rule engine needed.

## Testing Strategy

### Unit Tests
- Watcher store CRUD (mock DB or pgx mock)
- Scheduler logic (mock stores, verify polling)
- Prompt builder (input → expected prompt string)
- Alert evaluation (agent response → bool)
- Notification dispatch (mock HTTP for webhooks)
- API handlers (mock stores, verify JSON responses)

### Integration Tests
- Full watcher lifecycle: create → schedule → run → alert (testcontainers)
- Webhook notification delivery (httptest server)
- MCP tool integration (create watcher via MCP, verify in DB)

### What to Skip in `-short` Mode
- Database integration tests (testcontainers)
- Webhook delivery tests
- Full scheduler lifecycle tests
